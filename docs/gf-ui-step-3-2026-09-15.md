# UI step 3 — the routes: twelve public, fourteen gated under one mount, one adapter over one status table (2026-09-15)

**What this records.** UI-3 of `docs/gf-ui-refactor-plan.md` landed on 2026-09-15 as PR #488 (`staging` `43c417a`, commits
`531f8a4` and the lint lock `d832049`): every read the browser needs answers as an HTTP route through one adapter,
`src/routes/toolRoute.ts`, calling the same function its MCP tool calls; twelve public routes, fourteen gated under
`app.use('/api/research', requireResearcher, researchRouter)`; the per-page and gated tools split into a core and a handler, contract
unchanged; `GET /api/stats` and `/api/forensics` retired; the thesis body's `pages` carrying `trackedUrlId`; #487 ruled GATED and closed.
Backend only — no migration, no tool registered (the surface stays 45), no frontend file. It was built in a two-seat loop — a DEV seat
that wrote, a REVIEW seat that held the tree, graded against the contract and planted its own decoys — whose log is
`handoffs/R53-review-state.md`, outside this repository.

**What this step does not claim.** No page reads these routes yet; that begins at UI-4. The draft half of "a made-up id and a draft id
answer the same 404 bytes" was not observable on staging, which holds no draft thesis (§6). The `server.ts` mount itself is held in the
suite by a source scan; its behaviour was observed on staging, not in a test (§7).

## 2. The status table, as landed

One table, `TABLE` in `toolRoute.ts`, keyed by every code a routed core can return; a code outside it throws, and a core whose declared
refusal codes the table does not map does not compile (`Unmapped<B>`).

| the core's refusal | public door | research door |
|---|---|---|
| NOT_SURVEYED · NOT_PUBLIC · NOT_A_RECORD · NOT_A_CAPTURE · NO_SUCH_DIFF · NOT_PUBLISHED · NO_THESIS · NO_FRAMING · NO_SUCH_RULE · SESSION_NOT_FOUND | 404 `{ "error": "Not found" }` | 404, the refusal verbatim `{ error, code }` |
| AWAITING_DERIVATION | 409 verbatim | 409 verbatim |
| CHAIN_UNAVAILABLE | 503 verbatim | 503 verbatim |
| INVALID_RANGE · PHRASE_REQUIRED · INVALID_OUTCOME | 400 verbatim | 400 verbatim |
| INVALID_PARAMETER (the one code the routes add) | 400 `{ error, code }` — an unknown or repeated query key, `scope` among them, or a value the tool's own schema refuses | the same |
| NO_RESEARCHER | a thrown defect → 500 (no public core is asked a scope that needs a caller) | a thrown defect → 500 (the gate admitted one) |
| a value that is not a refusal, `{ live: false }` included | 200, the core's value as `JSON.stringify` — the tool's text less the MCP `environment` stamp | the same |

Before any route: 401 / 403 from `requireResearcher` at the mount, one body per kind whatever the id; 401 from `requireStagingAccess`
on staging. A path parameter reaches the core unparsed: a date where a timestamp belongs is the core's `NOT_A_CAPTURE`, never a 400.
