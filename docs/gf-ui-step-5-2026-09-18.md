## 3. THE MARKDOWN RENDERER AND ITS SUBSET — `docs/gf-ui-refactor-plan.md` :427's answer

:427 requires this step's dated doc to record **which** renderer and **which subset**. Read from
`src/lib/markdownToReact.tsx`, not remembered.

**The renderer: `markdown-it`, used as a PARSER and never as an HTML producer.** Its token stream is mapped to
React elements here, so a citation chip is a React element where its token stands and **nothing is ever handed to
`dangerouslySetInnerHTML`**. Configuration: the `commonmark` preset with `html: false`, `linkify: false`,
`typographer: false`, then `.enable(['table', 'strikethrough'])` — the same preset, never `'default'`, which would
switch `linkify` back on.

**THE SUBSET THAT RENDERS**

| | |
|---|---|
| blocks | paragraph · headings · bullet and ordered lists · list item · blockquote · **table** (`table · thead · tbody · tr · th · td`, each an open/close pair — twelve token types) · fenced and indented code · horizontal rule |
| inline | text · **strong** · **em** · **strikethrough** · inline code · autolink · soft break · hard break |
| headings are DEMOTED | `h1`→`h2`, `h2`→`h2`, `h3`→`h3`, `h4`/`h5`/`h6`→`h4`. The page owns `h1`; the researcher's structure starts below it |
| a table | gets a scrollport of its own (`md-table-scroll`), so "one column" governs the reading MEASURE and a table never widens the page (§6 :963) |
| alignment | honoured as `md-align-left/right/center` classes — the parser's `style="text-align:…"` is never carried through |
| bidi | a URL, a date in either form, a 64-hex hash and a 14-digit archive timestamp are each wrapped in `<bdi dir="ltr">`, inside a table cell exactly as in a paragraph |

**WHAT DOES NOT RENDER, AND WHY EACH ONE IS A DECISION**

- **Raw HTML** — `html: false`. "Every capability" never meant markup; HTML in the researcher's text renders as
  the text it is.
- **Linkify** — off, so a bare URL stays isolated text rather than becoming a link nobody chose. A CommonMark
  autolink, `<https://…>`, is a link the researcher wrote and does render.
- **Task lists and footnotes** — ruled OUT by the researcher, 2026-09-18, and written into §17 :538. Both need a
  plugin, and a thesis is an argument, not a working document. Their marks stay in the text as written.
- **An image renders its ALT TEXT and no `<img>`** — so nothing in the researcher's Markdown causes a public page
  to fetch an external resource.
- **A token type the map does not know renders as its own source text**, never silently dropped.
- **A citation token renders as NOTHING in the nine prose fields.** §17 :538 gives chips to THE TEXT, which
  resolves them against the body's mentions; these fields carry no resolved citations, so a token could only reach
  a reader as its own `0x…` name — an id shown as text, which §4 :167 forbids. It is cased.

**THE RUNTIME** is unchanged from the step's original brief: the pages render on the server, the share metadata is
composed from the body (§32 :822–:823), and TipTap is not used anywhere.

## 5. THE ARCHIVE WAS WEARING THE RESEARCHER'S VOICE

`RecordPane` rendered a captured page's text, a diff chunk and a trajectory's claim text through
`ResearcherWords` — the component whose marker `[data-researcher-words]` means *"the researcher wrote this"* and
whose selector applies their serif. **Those three values are the ministry's words, held in the archive.**

It is why the Markdown rule could not live in `ResearcherWords`: putting it there would have parsed the three
values §16 :521 forbids parsing, and a `#` or `*` standing in a captured page would re-interpret what the record
says — an evidence change wearing a display change's clothes.

So the rule went into a new component, `ResearcherProse`, and the archive left the marker. **The face did not
change and that was the requirement**: `.record-captured` now declares `font-family: var(--font-serif)` itself, so
it is a stated decision about the record rather than a side effect of the wrong voice's marker. Measured before
and after on the real body: `frankHebrew` · 15 px · 25.5 px · `pre-line` · `max-height: 420px` ·
`overflow-y: auto` · 4,539 characters — identical, with `clientHeight` 418 against `scrollHeight` 6021, so §18
:569's *"long content scrolls"* is intact and the 91 %-locked evidence of an earlier round has not returned.
`[data-researcher-words]` now marks **2** blocks on the thesis page where it marked 3, both the researcher's.

## 8. THE DEFECT THE FIXTURES COULD NOT SEE, AND WHY

The researcher asked whether „נימוקי הפרסום" appeared as one block because the text had no formatting or because

newlines over three blank-line breaks**, rendering with `childElementCount: 0` under `white-space: normal` — four

very fixture that hid the bug. This is the third time this shape has been paid for.
