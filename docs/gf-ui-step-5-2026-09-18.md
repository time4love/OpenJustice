## 3. THE MARKDOWN RENDERER AND ITS SUBSET — `docs/gf-ui-refactor-plan.md` :427's answer

:427 requires this step's dated doc to record **which** renderer and **which subset**. Read from
`src/lib/markdownToReact.tsx`, not remembered.

**The renderer: `markdown-it`, used as a PARSER and never as an HTML producer.** Its token stream is mapped to
React elements here, so a citation chip is a React element where its token stands and **nothing is ever handed to
`dangerouslySetInnerHTML`**. Configuration: the `commonmark` preset with `html: false`, `linkify: false`,
`typographer: false`, then `.enable(['table', 'strikethrough'])` — the same preset, never `'default'`, which would
switch `linkify` back on.

**THE SUBSET THAT RENDERS**

| | |
|---|---|
| blocks | paragraph · headings · bullet and ordered lists · list item · blockquote · **table** (`table · thead · tbody · tr · th · td`, each an open/close pair — twelve token types) · fenced and indented code · horizontal rule |
| inline | text · **strong** · **em** · **strikethrough** · inline code · autolink · soft break · hard break |
| headings are DEMOTED | `h1`→`h2`, `h2`→`h2`, `h3`→`h3`, `h4`/`h5`/`h6`→`h4`. The page owns `h1`; the researcher's structure starts below it |
| a table | gets a scrollport of its own (`md-table-scroll`), so "one column" governs the reading MEASURE and a table never widens the page (§6 :963) |
| alignment | honoured as `md-align-left/right/center` classes — the parser's `style="text-align:…"` is never carried through |
| bidi | a URL, a date in either form, a 64-hex hash and a 14-digit archive timestamp are each wrapped in `<bdi dir="ltr">`, inside a table cell exactly as in a paragraph |

**WHAT DOES NOT RENDER, AND WHY EACH ONE IS A DECISION**

- **Raw HTML** — `html: false`. "Every capability" never meant markup; HTML in the researcher's text renders as
  the text it is.
- **Linkify** — off, so a bare URL stays isolated text rather than becoming a link nobody chose. A CommonMark
  autolink, `<https://…>`, is a link the researcher wrote and does render.
- **Task lists and footnotes** — ruled OUT by the researcher, 2026-09-18, and written into §17 :538. Both need a
  plugin, and a thesis is an argument, not a working document. Their marks stay in the text as written.
- **An image renders its ALT TEXT and no `<img>`** — so nothing in the researcher's Markdown causes a public page
  to fetch an external resource.
- **A token type the map does not know renders as its own source text**, never silently dropped.
- **A citation token renders as NOTHING in the nine prose fields.** §17 :538 gives chips to THE TEXT, which
  resolves them against the body's mentions; these fields carry no resolved citations, so a token could only reach
  a reader as its own `0x…` name — an id shown as text, which §4 :167 forbids. It is cased.

**THE RUNTIME** is unchanged from the step's original brief: the pages render on the server, the share metadata is
composed from the body (§32 :822–:823), and TipTap is not used anywhere.

## 12. AFTER IT LANDED — three defects a READER found on a phone, and the font ruling

Nothing below was visible to the 193 green cases that shipped in PR #513. All three were found by the researcher
holding the deployed page on a phone, which is the reading `docs/gf-ui-refactor-plan.md` §6 exists to require.

**1 · The researcher's Markdown still rendered as ONE BLOCK — and the parser was innocent.** Their question was
the diagnosis: *"if md is formatted, how does it not also generate the paragraphs?"* **It did.** `markdown-it`
produced four `<p>`; what it cannot do is say how far apart they sit. Measured rather than assumed: a `<p>` inside
a bare iframe computes a **16px** margin, and inside this app it computes **0** — the reset removes the browser's
own spacing, so rendered Markdown has none unless a rule restores it. The rule had been restored at exactly ONE
call site, as `ThesisText`'s `space-y-3` utility, which the nine prose fields never passed through. **Gaps 0,0,0
→ 12,12,12**; the body text unmoved. The rule now belongs to the prose (`.md-prose > * + *`). **Why no case saw
it:** every case in the file COUNTS BLOCKS — and counting blocks is the parser's question while separation is
CSS's. The new case is a SOURCE scan, because jsdom computes no cascade and a rendered gap there is 0 either way;
its decoy declares `margin-top: 0`, which would satisfy "the rule exists" and change nothing a reader sees.

**2 · THE FONT — measured first, then ruled.** The researcher reported that most of the page was "the less pretty
font". Measured by which face actually DRAWS — canvas width against the declared stack, against Times, against
sans — **everything was correct**: Frank Ruhl Libre on the body, Heebo on the chrome, nothing falling back. What
they had described was a PREFERENCE against §1.8, not a defect. Three options were rendered with the published
text and **the researcher chose C**, then **„א"** for the archive. Five sites moved to `--font-sans`; two keep the
serif, which is NOT retired — that would return R57's F8 — but narrowed to **A DOCUMENT BROUGHT VERBATIM THAT THE
PLATFORM DID NOT AUTHOR**: `.record-captured` and `.letter-body`. Measured after: claim, body, headings, rationale
and the small note all `heeboHebrew`; the archive `frankHebrew`; every one proved not a fallback.

**3 · The phone drawer would not close.** Reproduction, the researcher's: thesis → tap a date → the archive
full-screen → back-swipe → **home** → open the drawer → pick the thesis → *"I cannot close the menu"*. Measured:
`Shell.tsx` reads no route at all, and the drawer had three ways out — Escape, the scrim, the toggle — of which
following a link inside it was not one. The body stays `overflow: hidden` while it is open, so the page behind
cannot scroll and the drawer covers its own toggle: that is the "cannot close". **The same-route tap is the hard
case** — the drawer lists what was opened in this browser, so the entry chosen is usually the page already open
and `pathname` never changes. Proven at 390 px: `sameRoute: true`, `aria-expanded` still `true` after the tap.

**FOUND, and owed a step rather than a patch:** opening a record pushes **no history entry** (`history.length`
unchanged), while the design makes that record full-screen at phone width — so a back-swipe does not close the
record, it leaves the thesis. Whether the pane becomes addressable or only history-aware is a design question for
the shell's owner step.
