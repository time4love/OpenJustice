## 8. THE PRESS RATE, AND WHY IT IS UNMEASURABLE

Plan :678 asks the chain check's press rate to be read "from the backend's request log for the `…/chain` route —
never from the page, which records nothing." The page records nothing, as ruled. The log was read on
2026-09-20 with `railway logs --http --since 72h --lines 5000` from the repository root: **39 requests, all
since 06:12 UTC, the current deployment's, none to `/chain`.** The two presses of the staging exercise
(2026-09-20, before that deployment) are not in it; `--lines` above 5,000 is refused ("Invalid input"), and the
logs of a REMOVED deployment cannot be opened. **Railway's HTTP log, as this CLI reaches it, retains the current
deployment.** A press rate read from it is a rate since the last deploy, and this step deploys several times a
day. Recorded as a finding for §41: the measurement needs a log that survives a redeploy, or a counter the
backend writes — neither exists, neither is invented here.

## 9. WHAT THE STEP FOUND THAT NO BRIEF CARRIED

- **The appendix names fields, not envelopes** — four times in one step. The rule now: an envelope is written
  into the appendix from the interface and a real body BEFORE a parser is written from it.
- **`tsc` refuses what `npm test` runs** in the frontend's test tree: jest transpiles types away, so a union of
  two half-optional shapes ran green and failed the type-check. The type-check is the instrument, three times over.
- **Two closed findings can compose into a new defect** (no words + the pill = an empty capsule). Re-read the
  real body after each landing.
- **The laptop's `.env` names the retired Sepolia registry**, so a local chain answer of "not registered" is the
  laptop's; staging answered TRUE at index 22.
- **`it.failing` counts as passed** and may not land.
- **A baseline blob is not a backup of a working tree**; a shared checkout is read (`reflog -3`, the branch, the
  porcelain) before any git write.
- **The `noUncheckedIndexedAccess` ratchet fails on an unlocked improvement**; a decrease that the diff explains
  arithmetically (five `members[0]` reads → one guarded `.at(0)`, 17 → 12) is locked from that arithmetic and
  confirmed by CI's line, never from a laptop's count.
