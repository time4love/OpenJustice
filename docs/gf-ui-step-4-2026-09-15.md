# UI step 4 — the layout: the chrome mounted once, one nav list keyed by identity, the document's locale, the share image (2026-09-15)

**What this records.** UI-4 of `docs/gf-ui-refactor-plan.md` landed on 2026-09-15 in three PRs to `staging`: **#490** (`2354e08`, commit
`2978a9e`) — what every page carries, mounted once in `app/[locale]/layout.tsx`: the name, the nav from ONE list keyed by identity, the
locale control, the footer, the banner; the sixteen page-level header imports removed; the chat widget and the staging debug console
unlinked; the root description replaced by approved copy; the mobile-first base in `globals.css`; `nav-is-the-map` written first. Then two
follow-ups the staging exercise found and the researcher ruled into the same step: **#491** (`56ea27b`, commit `d1a2740`) — the locale
layout becomes the root layout and renders `<html lang dir>`, because a locale switch left the English page right-to-left; **#492**
(`8b3e5c5`, commit `df41005`) — the share image moves into the locale segment, because #491 had silently dropped `og:image` from every
page. Frontend only: no backend file, no migration, the MCP surface 45. It was built in a two-seat loop — a DEV seat that wrote, a REVIEW
seat that held the tree, graded against the contract and planted its own decoys — whose log is `handoffs/R54-review-state.md`, outside
this repository.

**What this step does not claim.** Two nav entries lead to pages not yet built: `/corpus` (UI-7) and `/research` (UI-8) answer Next's
default 404, by the design's order (plan UI-4). That 404 carries no chrome, and after #491 it renders in Next's builtin document with no
`lang`, no `dir` and no stylesheet — ruled known until UI-10's `[locale]/not-found.tsx`. The admin view of the nav was not observable on
staging (no signed-in account is an admin); it is held by its fixture only. The legacy pages' own content is untouched and still says what
UI-9 and UI-10 retire.
